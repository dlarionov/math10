# 018 · Два репозитория и GitHub Pages

Статус: Реализована

## Цель и контекст

Сохранить одинаковую ветку main в GitFlic и GitHub и открыть каталог уроков как публичный сайт. Самостоятельные HTML и открытие с диска сохраняются.

## Границы

GitFlic остаётся origin, GitHub добавляется как github. У origin два push URL: обычный `git push origin main` отправляет main в оба сервиса. GitHub Pages публикует корень main; `.nojekyll` отключает обработку Jekyll. Сборка, зависимости, собственный домен и изменение содержания уроков не требуются.

## Сценарий

Перед работой fetch обоих remote и просмотр расхождений. Перед отправкой — проверка проекта, staged-снимка и истории на приватность. После отправки — независимая сверка hash main на обоих сервисах: отправка в два адреса не является атомарной. После push в GitHub сайт обновляется автоматически.

## Критерии готовности

- [x] Инструкции описывают оба remote и последствия push для публичного сайта.
- [x] Одинаковый commit main доступен в обоих репозиториях без force-push.
- [x] Pages настроен на main, корень; каталог и все уроки доступны по HTTPS.
- [x] Проверены статические ссылки и приватность; ограничения записаны.

## Реализация

1. Проверить чистоту Git, удалённые ветки и права GitHub.
2. Добавить remote и push URL, `.nojekyll`, обновить документацию и запись решения.
3. Выполнить проверки, коммит, аудит истории и push в оба сервиса.
4. Включить Pages через GitHub API и проверить опубликованные HTML.

## Проверки и ограничения

Секреты используются только в памяти. Сетевые операции требуют инструментальной эскалации и разового safe.directory; глобальные настройки не меняются.
